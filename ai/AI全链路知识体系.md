# <1>、AI 知识体系构造

## 开篇总览

### 核心主线（所有知识点围绕此展开）

- 整个 AI 领域的终极目标：构建能解决实际问题的工业级智能体 Agent，解决实际问题

- 所有底层技术（数学、机器学习、深度学习、大模型）都是为了打造 Agent 的 "大脑"

- 所有工程化技术（模型工程化 + Agent 工程化）都是为了让 Agent 能低成本、高效率、安全地运行

- 所有安全伦理问题都是 Agent 大规模落地后必然产生的问题

### 开篇误区澄清（先破后立，避免后续混淆）

| 常见误解（❌） | 精准表述（✅） | 
| -- | -- |
| PyTorch 是模型 | PyTorch 是深度学习计算框架，用于定义、训练和运行模型（如 Transformer、CNN），本身不包含任何模型参数或知识。 | 
| 大模型存了所有知识 | 大模型仅存储从训练数据中压缩出的通用常识与模式，不具备事实准确性；高精度、时效性知识需通过 RAG 从外部权威源动态检索注入。 | 
| 训练模型用了遗传算法 | 遗传算法等进化策略仅用于超参数搜索或神经架构搜索（NAS）等前置阶段；模型主体训练完全依赖基于梯度的优化（如 AdamW + 反向传播）。 | 
| Skill 就是工具调用 | Skill 是封装了工具调用、输入校验、错误重试、结果解析与业务逻辑的完整原子能力单元，而非裸 API 调用。 | 
| Agent 工程化就是模型量化 | 模型工程化聚焦计算效率（量化/编译/部署），而 Agent 工程化聚焦任务流可靠性（记忆管理、规划回退、工具协同、状态持久化）。二者目标不同，常需协同。 | 
| 大模型的上下文就是记忆 | 大模型上下文是临时、易失、长度受限的输入缓冲区；长期、结构化、可更新的记忆必须由外部向量库或数据库实现。 | 
| 大模型天生会规划 | 大模型可生成看似合理的计划，但缺乏目标一致性、状态感知与回退机制；工业级 Agent 必须引入独立规划器（如 LLM+PDDL、状态机、树搜索）保障可靠性。 | 
| 微调（Fine-tuning）能让模型记住新知识 | 微调调整的是模型的通用行为偏好（如格式、风格、能力倾向），无法可靠注入精确事实；新增知识仍需 RAG 或参数高效更新（如 LoRA + 知识蒸馏）。 | 


## 一、底层数学与工具基础

### 1.1 必备数学基础（所有 AI 算法的共同根基）

#### 1.1.1 线性代数

- 核心原理：所有 AI 模型的计算本质都是张量（多维数组）的线性变换。输入数据被转换为张量后，通过矩阵乘法、加法等运算完成特征提取和预测。

- 关键概念：

	- 张量：标量（0维）、向量（1维）、矩阵（2维）、高维张量（3维及以上，如图像、视频）

	- 矩阵乘法：神经网络中权重与输入特征的核心运算，实现特征的线性组合

📌【必记】线性代数是 AI 的"算术"，所有模型的底层计算都基于张量运算。

#### 1.1.2 微积分

- 核心原理：通过导数和偏导数计算函数的变化率，为模型权重更新提供方向。

- 关键概念：

	- 导数：单变量函数的变化率

	- 偏导数：多变量函数对某一个变量的变化率

	- 梯度：多变量函数所有偏导数组成的向量，指向函数值增长最快的方向

	- 链式法则：复合函数求导的方法，是反向传播算法的数学基础

📌【必记】梯度 = 损失函数变化最快的方向；梯度下降 = 沿着梯度反方向微调权重，是模型主体训练的唯一方式。

🔗 参见第 3.3 章 —— 仿生算法无梯度，只能做前置寻优，不参与主体训练。

#### 1.1.3 概率统计

- 核心原理：用概率分布描述数据的不确定性，通过最大似然估计等方法让模型拟合数据分布。

- 关键概念：

	- 概率分布：描述随机变量取值的概率规律（如正态分布、伯努利分布）

	- 最大似然估计：找到使观测数据出现概率最大的模型参数

	- 贝叶斯定理：描述条件概率之间的关系，是贝叶斯机器学习的基础

#### 1.1.4 信息论

- 核心原理：用熵量化信息的不确定性，通过交叉熵衡量模型预测与真实标签之间的差异。

- 关键概念：

	- 熵：描述随机变量的不确定性程度，熵越大，不确定性越高

	- 交叉熵：衡量两个概率分布之间的差异，是分类任务最常用的损失函数

📌【必记】交叉熵损失函数是深度学习分类任务的标准损失函数。

### 1.2 核心工具生态

- 深度学习框架：PyTorch/Torch（Python版Torch，动态图优先，研究与工业界主流）、TensorFlow

- 机器学习工具：Scikit-learn（传统机器学习算法库）

- 大模型工具：LangChain（Agent开发框架）、LlamaIndex（RAG检索框架）、LangGraph（规划与多Agent编排）

- 优化工具：Optuna（超参数自动寻优，内置GA、PSO等仿生算法）

- 模型转换工具：ONNX（开放神经网络交换格式，跨框架模型转换）

- 推理引擎：ONNX Runtime（通用推理引擎）、TensorRT（NVIDIA GPU推理加速）、RKNN（瑞芯微NPU推理引擎）

- Agent 工具：@pi0/skills（Skills包管理器）、openskills（公共技能库）、RTK（CLI输出压缩）、DCP（动态上下文裁剪）

💬 工具边界：PyTorch管训练，ONNX管转换，RKNN管部署，LangGraph管编排。不同环节用不同工具，不要越界使用。

### 本模块核心结论

1. 线性代数、微积分、概率统计和信息论是所有 AI 算法的数学基础，缺一不可。

1. 梯度和梯度下降是深度学习的核心，是模型主体训练的唯一方式。

1. 工具生态是 AI 落地的基础，不同工具对应不同的开发环节，边界清晰。

1. 所有后续模块的原理都建立在本模块的数学基础之上。

## 二、机器学习基础

### 2.1 机器学习三大范式

#### 2.1.1 监督学习

- 核心原理：使用带标签的训练数据，让模型学习输入到输出的映射关系。

- 核心任务：

	- 分类：预测离散标签（如图片分类、垃圾邮件识别）

	- 回归：预测连续值（如房价预测、销量预测）

- 代表算法：线性回归、逻辑回归、决策树、随机森林、SVM

- 深度学习用它来做**图像分类**（给你猫狗标签）、**语音识别**（给你文本标签）。

#### 2.1.2 无监督学习

- 核心原理：使用无标签的训练数据，让模型自动发现数据中的模式和结构。

- 核心任务：

	- 聚类：将相似的数据分组（如用户分群、异常检测）

	- 降维：将高维数据映射到低维空间（如PCA、t-SNE）

- 代表算法：K-means、DBSCAN、PCA

- 深度学习用它来做**生成式**（GAN生成图片）、**自监督预训练**（BERT/MaskGAN，通过掩码预测自造标签）。

#### 2.1.3 强化学习

- 核心原理：智能体通过与环境交互，根据获得的奖励信号不断优化行为策略，以最大化长期累积奖励。

- 核心概念：

	- 马尔可夫决策过程（MDP）：描述强化学习问题的数学框架

	- 策略：智能体的行为函数，决定在给定状态下采取什么动作

	- 奖励：环境对智能体动作的反馈信号

- 代表算法：Q-learning、DQN、PPO

- 深度学习用它来做**决策控制**（AlphaGo下棋、机器人运动规划）。

🔗 参见第 4.1 章 —— 强化学习是 RLHF（大模型对齐技术）的基础。

### 2.2 核心通用概念

- 过拟合 / 欠拟合：过拟合是模型在训练数据上表现好，在测试数据上表现差；欠拟合是模型在训练和测试数据上表现都差。

- 泛化能力：模型对未见过的新数据的预测能力，是机器学习的核心目标。

- 偏差 - 方差权衡：偏差是模型预测的平均误差，方差是模型预测的波动程度；降低偏差通常会增加方差，反之亦然，需要找到平衡点。

- 损失函数：衡量模型预测与真实标签之间差异的函数，是模型训练的优化目标。

- 优化器：根据损失函数的梯度更新模型权重的算法（如 SGD、Adam）。

- 评估指标：衡量模型性能的指标（如准确率、精确率、召回率、F1值）。

❌ 传统机器学习不会被深度学习完全取代，二者是互补关系。传统机器学习适合小数据、结构化数据任务，可作为 Agent 的辅助工具。

### 本模块核心结论

1. 机器学习分为监督学习、无监督学习和强化学习三大范式，各自适用于不同的任务场景。

1. 泛化能力是机器学习的核心目标，过拟合和欠拟合是训练过程中最常见的问题。

1. 强化学习是序列决策任务的核心方法，也是大模型对齐技术的基础。

1. 深度学习是机器学习的一个分支，专注于深度神经网络的研究与应用。

**区别**：传统机器学习（如线性回归、SVM）也能实现这三范式，但**深度学习**的优势在于“端到端”——输入原始像素/波形，直接输出动作或标签。传统ML需要人工提取特征。

**关系：三大范式**是“问题维度”**，深度学习**是“解法维度”**。** 深度学习**不是**第四大范式，而是**实现**三大范式的一种**高级手段**。

## 三、深度学习核心

### **3.0 总结概括**

1. **层级1：深度学习通用底层原理（数学理论基石）**：是所有训练框架、网络架构都必须遵循的统一数学规则，包含神经元运算公式、激活函数、前向传播、反向传播、梯度下降等核心理论，属于纯理论体系，无代码实现、无硬件运行行为。

1. **层级2：深度学习训练推理框架（运算载体）**：包含 PyTorch、TensorFlow、JAX、MXNet 四大主流框架。作为代码化运行载体，负责将底层数学理论落地，提供张量运算、自动微分、GPU/NPU硬件加速核心能力。所有网络架构的代码实现，完全依赖该层级框架算子完成全部运算。

1. **层级3：神经网络拓扑架构（模型骨架）**：包含 CNN、RNN/LSTM、Transformer、Mamba/RWKV 四大主流架构。是专属的数据处理结构方案，定义网络层与层之间的数据交互逻辑、特征提取方式。并非单纯的结构示意图，是可被训练框架实例化、编译、运行的完整可执行网络代码。

1. **层级4：Hugging Face 上层工具生态**：属于跨框架、跨架构的标准化封装工具，不参与任何数值计算。核心作用是统一模型权重格式、模型加载接口、数据预处理、微调流水线，屏蔽底层训练框架和网络架构的差异，实现各类模型开箱即用。

底层数学原理约束规则 → Transformer 架构设计数据流向 → PyTorch 框架执行矩阵 / 注意力数值计算 → Hugging Face transformers 加载权重、组装 prompt、调度框架推理

> **【表补充说明】**

> 1. 关于“主干架构”中的术语归属“双塔编码器（Two-Tower）”和“交叉编码器（Cross-Encoder）”是多模态模型的具体实现方式，属于第3层（模型架构）→ Hybrid混合架构的子类：双塔：两个独立编码器分别处理不同模态，最后通过对比学习对齐（典型：CLIP = ViT视觉塔 + Transformer文本塔）。交叉编码器：将多模态输入拼接后送入同一编码器，让注意力机制跨模态交互（典型：Flamingo、VLMO）。

> 2. 为什么“是否基于Transformer”一栏有例外？视觉模型中的ResNet、YOLOv5及之前版本基于CNN，音频模型中的WaveNet基于因果卷积，它们不属于大模型范畴，但在特定任务上仍有广泛使用。2020年后的大模型（包括现代ViT、Whisper、LLM、多模态模型）基本全部基于Transformer或其变体。

> 3. 为何不把GNN、推荐系统、扩散模型等单独列为第五大类？图神经网络（GNN）：处理图结构数据（社交网络、分子结构），其核心输入仍可归为结构化数据，通常在PyTorch Geometric等专用库上开发，不参与上述四类的模态划分逻辑。推荐系统模型：处理用户-物品交互矩阵，属于协同过滤/序列预测任务，本质是表格数据或序列数据的特例。扩散模型（Stable Diffusion）：输入为文本+噪声，输出为图像，其“文本→图像”的跨模态特性可归入多模态模型范畴，底层Unet主干基于CNN/Transformer。强化学习模型：输入为环境状态（图像/向量），输出为动作策略，其感知部分仍依赖视觉或结构化输入，通常叠加在上述四类之上。因此，上表聚焦按输入数据类型划分的四大主流模态，垂直领域分支作为补充说明不单独列表。

> 4. 各模态的推理路径差异（对应表二）视觉/音频模型 → ONNX → TensorRT/OpenVINO/RKNN（通用路径通畅），LLM → 很少走ONNX，通常走 vLLM / TensorRT-LLM / TGI 等专用推理栈（因需KV Cache管理和PagedAttention等特殊优化）多模态 → 视觉部分走ONNX，LLM部分走专用栈，需拼接部署

> 5. 表三与表二（计算框架对比表）的关联**表二中的“全功能训练框架（PyTorch/TF/JAX）”是生产这些模型的“工厂”，表三中的“推理框架适配”和“ONNX导出可行性”则决定了这些模型训练完后如何走向部署（表四的ONNX→RK3588流水线）。三者构成“训练→导出→部署”的完整链路。

### 3.1 **通用底层原理（第一层：理论根基）**

- 核心原理：通过堆叠多层非线性变换的神经网络，自动从数据中学习层次化的特征表示。

- 神经网络基本单元：

	- 神经元：接收输入，进行线性变换（y=wx+b），然后通过激活函数引入非线性

	- 全连接层：每个神经元与上一层所有神经元相连，实现特征的全局线性组合

	- 激活函数：引入非线性，让神经网络能够拟合复杂的非线性函数（如ReLU、SiLU、GELU）

	- 归一化层：加速训练、稳定梯度（如Batch Normalization、Layer Normalization）

- 训练核心流程：

1. 前向传播：输入数据通过网络层层计算，得到预测结果

1. 损失计算：用损失函数计算预测结果与真实标签之间的差异

1. 反向传播：根据链式法则，从输出层到输入层逐层计算损失对每个权重的梯度

1. 梯度下降：优化器根据梯度更新模型权重，减小损失

📌【必记】判别式模型（分类/回归）的训练流程统一为前向→损失→反向→梯度下降，区别仅在特征提取模块。生成式模型（GAN、扩散模型）训练流程各有不同，不适用此统一描述。

💬 判别式模型学的是"边界"（这张图是猫还是狗），生成式模型学的是"分布"（猫长什么样，然后画一只）。任务不同，训练逻辑不同。

### 3.2 训练推理框架（第二层：运算载体）

- 核心定位：也常被称作计算运行引擎，是将底层数学理论落地执行的代码运行基座；为 CNN、RNN、Transformer、Mamba/RWKV 全部网络拓扑结构，提供张量运算、自动求导、GPU/NPU 硬件调度加速、优化算子等底层执行能力。

- 强制约束：任意一种网络架构，自身只定义数据流转拓扑逻辑，无法独立完成数值运算；必须调用本层框架内置算子，才能执行前向传播、反向梯度更新整套计算流程。

- 四大主流框架：PyTorch、TensorFlow、JAX、MXNet

1. PyTorch（Torch）：动态图执行机制，当前大模型领域行业绝对主流；LLM、VLM、Mamba、RWKV 绝大多数开源模型均基于 PyTorch 完成训练；同时是 Hugging Face 生态默认后端。

1. TensorFlow：静态图架构，传统计算机视觉工业项目、移动端部署场景使用广泛，配套 TFLite 轻量化推理工具链。

1. JAX ：谷歌自研框架，支持高效自动向量化与大规模分布式训练；Gemini 系列模型、大量 Mamba 类 SSM 实验模型依托 JAX 开发训练。

1. MXNet ：早年主流深度学习框架，如今市场占有率大幅萎缩，仅少量遗留老旧业务系统仍在使用。

#### **3.2.1 自动微分**

**1. 什么是自动微分？（一句话定义）**

**自动微分（Autograd）** 是深度学习框架内置的“求导计算器”。它能自动追踪你模型里的每一个数学操作（加减乘除、矩阵乘法、激活函数），并精确算出损失函数（Loss）对每一个权重参数（Weight）的偏导数（梯度）。

**2. 它在训练中具体干了什么？（核心机制）**

没有它，深度学习就没法训练。它是**反向传播（Backpropagation）** 的代码实现：

- 前向跑一遍：输入数据算出预测结果，并算出总损失 Loss。

- 自动反向追踪：框架立刻根据 Loss，沿着刚才计算的路径**自动倒推**，用链式法则算出每一层参数的梯度（即“权重该调大还是调小”）。

- 交给优化器：算出的梯度传给优化器（如 Adam），优化器拿着梯度去更新权重。

**一句话**：自动微分 = 框架自带的“梯度计算工厂”，负责把复杂的数学求导自动化。

**3. 为什么它是训练框架和推理引擎的“绝对生死线”？（核心区隔）**

| 对比维度 | **全功能训练框架**（PyTorch/TF/JAX） | **纯推理引擎**（ONNX Runtime/TensorRT） | 
| -- | -- | -- |
| **是否含自动微分** | **✅ 包含** | **❌ 不包含** | 
| **内部实情** | 内置了完整的 autograd 引擎，运行时动态构建计算图并实时求导。 | 只有**前向计算**的算子（Conv、MatMul、Add），完全没有反向求导的代码逻辑。 | 
| **能做什么** | 既能算前向（推理），也能算反向（训练）。 | **只能做前向计算**。输入权重 → 算出结果，结束。 | 
| **能不能训练** | **能**。因为能算梯度，所以可以调用优化器更新权重。 | **绝对不能**。因为根本没装“求导”这个功能模块，给它 Loss 它也不知道怎么反传梯度。 | 


**4. 结论（划重点）**

- 只要是需要“学习”更新权重的过程，底层绝对依赖自动微分。

- 只要推理引擎声称自己“不支持训练”，本质上就是因为它们的代码库里**完全移除了自动微分（Autograd）模块**，只保留了轻量级的前向计算算子，以此换取更小的体积和更极致的推理速度。

**计算框架与推理引擎分类总览（专项对比表）**

| 类别 | 框架名称 | 训练支持 | 推理支持 | 是否含自动微分（核心区隔） | 主要场景与现状说明 | 
| -- | -- | -- | -- | -- | -- |
| **全功能训练框架** | PyTorch | ✅ | ✅ | **✅ 含自动微分**（动态图，反向传播完整） | LLM/VLM/Mamba训练与推理，绝对主流，市占率90%+。 | 
|   | TensorFlow | ✅ | ✅ | **✅ 含自动微分**（静态图 + Eager模式） | 工业CV、移动端TFLite部署，存量系统为主。 | 
|   | JAX | ✅ | ✅ | **✅ 含自动微分**（函数式纯函数变换，jit + grad组合） | 前沿科研、大规模分布式（Gemini、Mamba实验性实现）。 | 
|   | MXNet | ✅ | ✅ | **✅ 含自动微分**（已停止维护） | Apache归档，退出主流生态，无LLM支持。 | 
| **纯推理加速引擎** | ONNX Runtime | ❌ | ✅ | **❌ 不含自动微分**（仅执行前向计算） | 跨平台部署，NPU加速（RK3588、华为昇腾）。**不支持训练。** |

|   | OpenVINO | ❌ | ✅ | **❌ 不含自动微分**（仅硬件指令集映射） | Intel CPU与VPU边缘端推理加速。 | 
|   | RKNN Runtime | ❌ | ✅ | **❌ 不含自动微分**（仅NPU算子调度） | Rockchip NPU专用推理栈。 | 


### 3.3 四大主流神经网络架构（第三层：模型骨架）

由固定数学运算模块组合而成的**完整拓扑结构方案**，规定数据流转方式：

1. CNN：**卷积滑动采样拓扑**，空间特征提取专用，图像、视觉主干（ViT 除外）；靠滑动卷积核提取局部空间特征。

1. RNN/LSTM/GRU：**循环门控状态传递拓扑**，原生时序序列结构，逐 token 循环传递状态；老一代文本、语音标配，长距离依赖易梯度消失。

1. Transformer：**多头注意力全局交互拓扑，**自注意力机制，全局并行建模序列；现在 LLM、VLM 绝对主流（GPT、Qwen、Llama 全是 Decoder Transformer）。

1. SSM 状态空间系列（Mamba/RWKV）：**SSM 线性状态递推拓扑，**新一代线性时序架构，替代 Transformer 的候选；无注意力、O (n) 复杂度、长文本显存占用远更低，属于新兴第四大路线。

#### 3.3.1 CNN 卷积神经网络

- 核心原理：通过卷积核在输入数据上滑动，提取局部特征；利用权值共享减少参数数量；通过池化层降维，扩大感受野。

- 核心模块：

	- 卷积层：提取局部特征（如边缘、纹理、形状）

	- 池化层：降低特征图尺寸，减少计算量，增强特征的鲁棒性

	- 全连接层：将卷积提取的特征映射到输出空间

- 适用场景：视觉感知任务（Agent 的"眼睛"），如图像分类、目标检测、图像分割

- 代表模型：ResNet、YOLO、VGG、MobileNet

#### 3.3.2 RNN/LSTM 循环神经网络

- 核心原理：通过循环隐状态传递历史信息，处理序列数据。LSTM通过门控机制（输入门、遗忘门、输出门）解决了传统RNN的梯度消失问题。

- 适用场景：短时序任务（如语音识别、短句翻译），已基本被Transformer取代

- 代表模型：LSTM、GRU

- 在 NLP 领域基本被取代，但在端侧低功耗时序任务中仍有价值，可与状态空间模型一并关注”。

- 在 NLP 领域确实被 Transformer 取代，但在以下工业场景中，RNN/LSTM 变体仍是主力：

	- 时序预测/异常检测：多元时间序列建模，LSTM/GRU 与 Transformer 各有胜负。

	- 传感器信号处理：实时性要求高、序列极长的工业信号，线性复杂度的状态空间模型（Mamba系）和 LSTM 都在用。

	- 低算力端侧设备：某些 STM32/低端 MCU 上，LSTM 推理算力开销远低于 Transformer。

#### 3.3.3 Transformer

- 核心原理：通过多头自注意力机制，直接计算序列中每个位置与所有位置的关联，实现全局上下文建模；通过位置编码引入序列的位置信息。

- 核心模块：

	- 多头自注意力：将输入特征映射为多个头，分别计算注意力，然后拼接结果，捕捉不同维度的语义关联

	- 前馈网络（FFN）：对每个位置的特征进行非线性变换

	- 残差连接与LayerNorm：加速训练，防止梯度消失

- 适用场景：语言、逻辑、多模态任务（Agent大脑的核心）

- 代表模型：GPT、LLaMA、BERT、ViT

📌【必记】纯 Transformer 大模型不含卷积。

❌ 卷积不是所有模型必备，纯大语言模型可以完全不用卷积。

#### 3.3.4 Mamba/RWKV 状态空间模型

- 核心原理：通过状态空间模型（SSM）的线性递推机制，实现长序列建模，时间复杂度为O(n)，远低于Transformer的O(n²)。

- 适用场景：超长上下文Agent、大模型推理加速

- 代表模型：Mamba、RWKV

- RWKV：国产开源 SSM，对标 LLM，纯文本大模型架构，兼容 HF 格式

- Mamba：通用状态空间块，可搭 LLM、VLM、语音全模态，属于 SSM 标杆

#### 架构选型速查

| 架构 | 适用场景 | 一句话建议 | 
| -- | -- | -- |
| CNN | Agent视觉感知 | 看图就用它 | 
| RNN/LSTM | 短时序任务 | 基本被取代，低算力端侧使用 | 
| Transformer | Agent大脑（语言/推理） | 当前绝对主力 | 
| Mamba/RWKV | 超长序列/推理加速 | 长上下文未来方向 | 


### 3.4 Hugging Face 生态层（第四层：上层应用封装）

- 核心定位：独立于引擎、架构的标准化工具链与模型仓库，无底层计算能力

- 核心组件：transformers、AutoModel/AutoTokenizer、safetensors 权重格式、peft 微调工具

- 作用：**套在四大框架之上**，封装 LLM/VLM 权重、对话模板、加载 / 推理 / 微调流水线，不做底层算力计算

	- 一套加载接口兼容 **CNN/RNN/Transformer/Mamba 全部架构**

	- 自动适配 PyTorch/TensorFlow/JAX 三大计算引擎

	- 统一 HF 模型文件夹规范（config.json、分词器、分片权重）

	- 内置对话模板、图像预处理、批量推理逻辑

- 依赖链路：HF 工具 → 实例化对应架构网络 → 调用计算引擎完成前向传播推理 / 训练

### 3.5 深度学习优化技术

#### 3.5.1 梯度类优化（主体训练唯一方式）

- 核心原理：根据损失函数的梯度，沿着梯度反方向微调模型权重，逐步减小损失。

- 代表算法：

	- SGD（随机梯度下降）：每次使用一个样本更新权重，速度快，波动大

	- Adam：结合动量和自适应学习率，收敛快，稳定性好，是目前最常用的优化器

- 学习率调度：训练过程中动态调整学习率，前期用大学习率快速收敛，后期用小学习率精细调整。

❌ 在**深度神经网络**的主体训练中，基于梯度的优化是**绝对主流且唯一工业级可行方式** 。

但从AI全局看存在两个例外：

- 决策树/随机森林/XGBoost：原理不是梯度下降。

- 进化策略（Evolution Strategies）：可以作为强化学习中策略网络的替代训练方法，直接优化参数，这属于“主体训练”。

#### 3.5.2 非梯度类优化（仅前置寻优）

- 核心原理：不依赖梯度，通过群体随机搜索和优胜劣汰迭代寻优，适合离散组合优化问题。

- 代表算法：仿生智能算法（GA遗传算法、PSO粒子群算法、ACO蚁群算法）

	- GA遗传算法：模仿生物进化，通过选择、交叉、变异迭代筛选最优解

	- PSO粒子群算法：模仿鸟群觅食，通过粒子向自身最优和全局最优位置靠拢寻优

- 适用场景：网络结构搜索NAS、超参寻优、初始权重优化

📌【必记】仿生算法仅用于前置结构/超参/初始权重寻优，选完即退场，不参与主体权重训练。

🔗 参见第 1.1.2 章 —— "梯度下降是模型主体训练的唯一方式"。

#### 3.5.3 正则化

- 核心原理：通过限制模型的复杂度，防止过拟合，提升泛化能力。

- 代表技术：Dropout（训练时随机丢弃部分神经元）、L1/L2正则（在损失函数中加入权重的惩罚项）、早停（当验证集损失不再下降时停止训练）

### 本模块核心结论

1. 深度学习的核心是神经网络。判别式模型训练流程统一，生成式模型各有不同。

1. 四大主流架构各有优劣，Transformer是当前大模型的核心架构，Mamba是长序列建模的未来方向。

1. 梯度类优化是模型主体训练的唯一方式，仿生算法仅用于前置寻优，二者边界清晰。

1. 正则化是防止过拟合、提升模型泛化能力的关键技术。

1. 深度学习完整四层栈：底层数学原理 → 训练推理框架 → 网络架构骨架 → HuggingFace 上层工具生态，层层依赖、自上而下运行。

## 四、大模型基础

### 4.1 大模型核心技术栈

#### 4.1.1 预训练

- 核心原理：使用海量**无标注**文本数据，通过自监督学习任务（如预测下一个Token），让模型学习通用的语言规律和常识知识，并将这些知识压缩进权重参数中。

- 核心特点：预训练后的大模型具备通用的语言理解和生成能力，可通过微调适配各种下游任务。

#### 4.1.2 微调

- 核心原理：在预训练模型的基础上，使用少量**标注数据**继续训练，让模型学会遵循指令、完成特定任务。

- 主流技术：

	- 全量微调：更新模型的所有权重，效果好，但计算成本高

	- SFT（监督微调）：使用人类标注的指令数据微调，让模型学会遵循指令

	- LoRA/QLoRA：低秩适配技术，只更新模型的少量参数，计算成本低，效果接近全量微调

#### 4.1.3 对齐

- 核心原理：让大模型的输出符合人类的价值观和偏好，避免生成有害、虚假、偏见的内容。

- 主流技术：

	- RLHF（基于人类反馈的强化学习）：先由人类标注员对模型输出进行排序，然后训练奖励模型，最后用强化学习算法优化大模型

	- DPO（直接偏好优化）：直接使用人类偏好数据优化模型，不需要奖励模型，更简单高效

🔗 参见第 2.1.3 章 —— RLHF基于强化学习原理。

### 4.2 大模型推理与增强技术

#### 4.2.1 原生推理

- 核心原理：自回归逐Token生成，即每次生成一个Token，然后将生成的Token加入上下文，再生成下一个Token，直到生成结束符。

- 核心特点：

	- 仅使用权重内压缩的通用常识知识

	- 不联网、不查库、不调用外部工具

	- 推理成本与输入输出Token数量成正比

📌【必记】原生大模型不联网、不查库，仅使用权重内压缩的通用常识。

#### 4.2.2 工业级增强推理：RAG 检索增强

- 核心原理：将外部知识库中的知识检索出来，与用户问题一起拼接成Prompt，喂给大模型，让大模型基于检索到的真实知识生成答案。

- 完整流程：

1. 用户提问

1. 问题解析与改写

1. 检索本地知识库/全网搜索引擎

1. 检索结果相关性排序与去重

1. 提取高可信度参考文本

1. 构建Prompt：系统指令 + 用户问题 + 检索参考资料

1. 送入大模型生成答案

📌【必记】RAG负责提供事实，大模型负责生成和推理，二者边界绝对清晰。

🔗 参见开篇分工总表中RAG和大模型的职责。

❌ 大模型不会自己主动联网搜索，所有检索动作由外部RAG模块完成。

### 本模块核心结论

1. 大模型的核心技术栈包括预训练、微调和对齐，预训练注入通用知识，微调让模型学会遵循指令，对齐让模型符合人类价值观。

1. 原生大模型仅使用权重内的知识，无法获取实时和精准的专业知识。

1. RAG检索增强是工业级大模型问答的标准实现方式，解决了大模型知识截止和大部分幻觉问题。

1. 大模型的推理成本与Token数量成正比，这是Agent工程化优化的核心动因。

🔗 参见第 6.2 章 —— Agent工程化的核心目标就是降低Token成本。

## 五、Agent 智能体（核心中的核心）

### 5.1 Agent 核心定义与五大组件

📌【必记】Agent = 大脑（大模型）+ 记忆 + 规划 + 工具 + Skills

大模型只是 Agent 的大脑，不是完整的 Agent。五大组件分工绝对清晰，缺一不可。

#### 5.1.1 大脑（大模型）—— 管决策、管语言、管推理

- 核心职责：决策、语言生成、逻辑推理

- 原理详解：作为 Agent 的核心，接收规划模块处理后的上下文，生成决策、推理过程和自然语言回答。

- 工程映射：RKLLM（本地NPU推理）、llama.cpp（CPU推理）、云端API（DeepSeek/GPT/Claude）

🔗 参见开篇分工总表中大脑的职责。

#### 5.1.2 记忆模块 —— 管什么记住、什么忘掉

- 核心职责：管理短期上下文、长期向量记忆、技能使用记录、动态加载与卸载

- 原理详解：工业级 Agent 采用四层标准化记忆架构：

1. 短期上下文记忆：当前对话窗口内的内容，直接送入大模型

1. 工作记忆：当前任务的中间执行状态

1. 长期向量记忆：历史对话和知识库内容，存储在向量数据库中

1. 技能记忆：已安装的 Skills 清单和使用记录

- 动态加载与卸载：根据当前任务需要，只将相关的记忆内容加载到上下文，无关内容卸载，避免上下文爆炸。

- 工程映射：LlamaIndex（记忆构建）+ Chromadb（向量存储）

🔗 参见开篇分工总表中记忆模块的职责，也为第 6.2 章的 DCP 动态上下文裁剪提供了基础。

💬 记忆不是存得越多越好。关键是"该记的记住，该忘的忘掉"——上下文窗口有限，把无关历史塞进去只会让大模型分心。

#### 5.1.3 规划模块 —— 拆任务、管步骤、能回滚

- 核心职责：任务拆解、步骤编排、执行状态管理、失败回滚、反思修正、多 Skill 组合编排

- 原理详解：将用户的复杂任务拆解为可执行的子任务，编排执行步骤，管理每个步骤的执行状态，当步骤失败时进行回滚和重试，任务完成后进行反思总结。

- 多 Skill 组合编排：根据任务需要，将多个 Skills 按照串行、并行或条件分支的方式组合起来，完成复杂的专业任务。

- 工程映射：LangGraph（精确状态机控制，推荐）、CrewAI（角色扮演式编排）、自写 while 循环（最轻量）

🔗 参见开篇分工总表中规划模块的职责。

#### 5.1.4 工具调用 —— 管执行单一动作

- 核心职责：执行单一外部动作（API/CLI/数据库/GPIO）

- 原理详解：作为 Agent 与外部世界交互的接口，接收规划模块的指令，执行单一的外部动作，并将结果返回给规划模块。一个工具只做一件事。

- 工程映射：MCP协议（标准工具集成方式）、自写硬件驱动函数（GPIO/摄像头/PWM封装）

⚠️ 工具 = 单一 API 调用；Skill = 完整工作流程 + 最佳实践 + 错误处理。二者不可混淆。

🔗 参见开篇分工总表中工具调用的职责。

#### 5.1.5 Skills —— 管专业工作流程

- 核心职责：提供专业工作流程、最佳实践、错误处理模板

- 原理详解：将特定领域的专业知识和工作流程封装成标准化的 Skill 包，让 Agent 无需重新学习，即可胜任专业任务。

- 工程映射：SKILL.md 文件 + @pi0/skills 包管理器 + openskills 社区库

🔗 参见开篇分工总表中 Skills 的职责，详细内容见第 5.3 章。

💬 五大组件协作示例：用户说"帮我检查这个传感器是否正常"。大脑判断意图 → 规划拆解步骤（初始化 → 读数 → 校验 → 报告）→ 调用工具执行 GPIO 读取 → 如失败则回滚重试 → 记忆存储结果 → 大脑生成最终报告。

### 5.2 单 Agent 主流架构模式

⚠️ 本节严格区分"架构模式"与"产品实例"。ReAct、Reflexion、Plan-Execute 是抽象设计模式；Claude Code、OpenCode 是具体终端产品。

| 模式 | 核心思想 | 关键特征 | 
| -- | -- | -- |
| ReAct | 推理与行动交织 | 每步先思考再行动，观察结果后调整。最基础、最常用的 Agent 循环。 | 
| Reflexion | ReAct + 长时反思记忆 | 任务结束后生成反思总结存入长期记忆，下次遇到类似任务能加载教训。 | 
| Plan-Execute | 先规划，后执行 | 接到大目标先生成完整任务清单，再逐步执行。AutoGPT 是此模式的代表实现。 | 
| 工业级混合 | 上述模式融合 | Claude Code 是典型产品实例：内部用 ReAct 类循环进行代码探索与修改，原生集成 Skills 标准。 | 


### 5.3 Agent 能力扩展：Skills 开放标准（2026 工业级标准）

- 起源：Anthropic Claude Code 2025.12.18 正式开放，已成为行业事实标准

- 核心原理：渐进式披露 → Agent启动时只加载SKILL.md清单（包含Skill的名称、描述、输入输出），当需要调用某个Skill时，再加载完整的指令和代码，彻底解决了一次性加载所有指令导致的上下文爆炸问题。

- Skill 文件标准结构：

	- 文件夹：每个Skill一个独立的文件夹

	- SKILL.md：包含YAML头（元数据）和Markdown指令（工作流程、最佳实践、错误处理）

	- scripts/：可选，包含Skill执行所需的脚本文件

- 通用工具生态：@pi0/skills（Skills包管理器，支持一键安装、卸载、更新）、openskills（社区维护的公共技能库）、add-skill（Skill生成工具）

- 与工具调用的本质区别：工具 = 单一 API，Skill = 完整工作流程 + 最佳实践 + 错误处理

- Skill 开发流程：编写 SKILL.md → 本地安装测试 → 发布到 openskills 社区分享

🔗 参见第 4.2.1 章 —— 渐进式披露原理解决了大模型上下文长度限制问题。

### 5.4 多 Agent 系统

- 主流架构：

	- 主从式：一个主控Agent负责任务分配和协调，多个专业Agent负责执行具体任务

	- 联邦式：多个平等的Agent协同工作，共同完成任务

	- 层级式：多层Agent分工，高层负责战略规划，低层负责战术执行

- 核心技术：角色分工、通信协议、任务分配、冲突解决

- 工程映射：AutoGen（多Agent协作框架）、CrewAI（角色驱动编排）、LangGraph（子图/层级图拓扑）

## 六、工程化落地（从实验室到生产）

### 6.1 模型工程化（优化计算量）

- 核心目标：让模型跑得更快、更省算力，降低推理延迟和硬件成本。

- 核心技术：

	- 量化：将模型的权重和激活从32位浮点数转换为16位、8位甚至4位整数，减少计算量和内存占用，精度损失很小

	- 剪枝：移除模型中不重要的权重和神经元，减少模型参数数量

	- 知识蒸馏：用大模型（教师模型）训练小模型（学生模型），让小模型具备接近大模型的能力

	- 标准部署链路：PyTorch模型→ONNX转换→RKNN量化→边缘设备NPU推理

📌【必记】模型工程化只优化模型计算量，不改变输入输出数据。

🔗 参见第 1.2 章 —— ONNX和RKNN属于工具生态。

### 6.2 Agent 工程化（优化数据量/Token成本）

- 核心目标：降低输入输出Token消耗，提升Agent运行效率，降低推理成本。

- 与模型工程化的本质区别：不改变模型本身，只优化输入输出数据。

- 适用范围说明：RTK、DCP、.opencodeignore等工具主要适用于CLI/编程型Agent（如Claude Code），非通用型Agent需按场景选用。

📌【必记】模型工程化优化计算，Agent工程化优化数据，二者边界清晰。

- 主流工具与技术：

	- RTK (Rust Token Killer)：CLI中间件，压缩ls、git diff等命令的输出，去除无关的格式和冗余信息，节省60%~90%输入Token

	- DCP (Dynamic Context Pruning)：插件，自动裁剪长对话历史，只保留与当前任务相关的内容，节省30%~50%上下文Token

	- .opencodeignore：类似.gitignore的配置文件，排除编译产物、构建目录、日志文件等无关文件，避免无效Token消耗

	- UltraPress：四层文本压缩算法，在保留语义的前提下大幅压缩文本长度

	- ACP (Auto Context Pruning)：自动去除上下文中的重复内容

	- Supermemory：跨会话高效记忆系统，将长期记忆存储在向量数据库中，按需加载

🔗 参见第 5.1.2 章 —— DCP和Supermemory与记忆模块协同；Token优化动因来自第4.2.1章。

### 6.3 MLOps 与 AIOps

- 核心目标：实现AI模型和Agent的全生命周期自动化管理，提升开发效率和系统稳定性。

- 核心内容：

	- 数据管理：数据采集、清洗、标注、版本管理

	- 模型版本管理：模型训练、版本控制、模型仓库

	- 监控与运维：模型性能监控、错误监控、资源监控

	- A/B测试：不同模型和Agent版本的对比测试

	- Agent全生命周期管理：Agent开发、测试、部署、升级、下线

	- 可观测性：Agent执行轨迹追踪、Token消耗监控、任务完成率统计（工具：LangSmith、LangFuse、AgentOps）

### **6.4 ****模型评测**

- GLUE/BLEU/ROUGE 等传统指标。

- Agent 评测：任务完成率、轨迹相似度、人评协议。

- RAG 评测：检索准确率、答案忠实度（Faithfulness）。

### 本模块核心结论

1. 工程化是AI从实验室走向生产的最后一公里，分为模型工程化和Agent工程化两个维度。

1. 模型工程化优化计算量，Agent工程化优化数据量，二者缺一不可。

1. RTK、DCP、.opencodeignore是当前Agent工程化的核心工具，能大幅降低Token成本。

1. MLOps和AIOps是大规模生产环境中AI系统稳定运行的保障。

## 七、安全伦理与法规

### 7.1 技术安全

#### 7.1.1 模型安全

- 反蒸馏：防止攻击者通过查询模型输出，蒸馏出模型的权重和知识，保护模型知识产权

- 对抗攻击防御：防止攻击者通过构造恶意输入，让模型产生错误的输出

- 模型窃取防护：防止攻击者直接窃取部署的模型文件

🔗 参见第 6.1 章 —— 反蒸馏是知识蒸馏技术的反向应用。

#### 7.1.2 Skill 安全

- Skill安全沙箱：隔离运行Skill代码，防止恶意Skill访问系统资源、窃取数据或破坏系统

- 权限控制：为每个Skill分配最小必要权限

- 输入输出过滤：过滤Skill的输入和输出，防止注入攻击和敏感信息泄露

- 恶意代码检测：扫描公共Skill库中的Skill，检测恶意代码

🔗 参见第 5.3 章 —— Skill安全是Skills开放标准落地的前提。

#### 7.1.3 数据安全

- 数据隐私保护：对训练数据和用户数据进行脱敏处理，防止隐私泄露

- 数据加密：对存储和传输中的数据进行加密

- 访问控制：严格控制数据的访问权限 

#### **7.1.4 ****越狱防御**

- Agent 时代更常见的**提示注入与越狱攻击**（Prompt Injection / Jailbreak）

- 针对 Agent 的提示注入防御、系统指令保护、输入输出内容安全护栏

### 7.2 2026 热点伦理问题（真实案例）

- 同事.skill：员工将自己的专业技能和工作经验封装成Skill，引发了职场隐私、知识产权归属和员工替代的争议

- 知识价值归属：RAG检索生成内容的版权归属问题，是原作者、知识库提供者还是大模型厂商，目前全球没有明确的法律定论

- 数字分身被遗忘权：欧盟AI法案明确要求，用户有权要求删除自己的数字分身和相关数据，即"被遗忘权"

- 算法偏见与公平性：Agent在决策过程中可能会继承训练数据中的偏见，导致歧视性结果

🔗 参见第 5.3 章 —— 同事.skill与Skills开放标准直接相关。

### 7.3 全球 AI 法规

- 欧盟AI法案：全球第一部综合性AI法规，将AI系统分为四个风险等级，对高风险AI系统实施严格监管

- 中国生成式AI服务管理暂行办法：对生成式AI服务的备案、数据安全、内容合规等方面做出了明确规定

- 美国AI行政令：要求联邦政府机构在使用AI时确保安全、可信和负责任

### 本模块核心结论

1. 安全伦理是AI大规模落地的前提，没有安全的AI系统没有商业价值。

1. 技术安全包括模型安全、Skill安全和数据安全，是AI系统的基础保障。

1. 随着AI技术的发展，出现了许多新的伦理问题，需要技术、法律和社会共同解决。

1. 全球AI法规正在逐步完善，企业和开发者必须遵守相关法律法规。
