# AI 知识体系构造

## 开篇总览

### 核心主线

整个 AI 领域的终极目标：构建能解决实际问题的工业级智能体 Agent。

- 所有底层技术（数学、机器学习、深度学习、大模型）都是为了打造 Agent 的"大脑"
- 所有工程化技术（模型工程化 + Agent 工程化）都是为了让 Agent 能低成本、高效率、安全地运行
- 所有安全伦理问题都是 Agent 大规模落地后必然产生的问题

🧠 核心认知：大模型（LLM）只是 Agent 的"大脑"，不是 Agent 本身。Agent = 大脑 + 记忆 + 规划 + 工具 + Skills。

## 一、底层数学与工具基础

### 1.1 必备数学基础

#### 1.1.1 线性代数

核心原理：所有 AI 模型的计算本质都是张量（多维数组）的线性变换。输入数据被转换为张量后，通过矩阵乘法、加法等运算完成特征提取和预测。

关键概念：

- 张量：标量（0维）、向量（1维）、矩阵（2维）、高维张量（3维及以上，如图像、视频）
- 矩阵乘法：神经网络中权重与输入特征的核心运算，实现特征的线性组合

🧠 核心认知：线性代数是 AI 的"算术语言"，所有模型的底层计算都基于张量运算。

#### 1.1.2 微积分

核心原理：通过导数和偏导数计算函数的变化率，为模型权重更新提供方向。

关键概念：

- 导数：单变量函数的变化率
- 偏导数：多变量函数对某一个变量的变化率
- 梯度：多变量函数所有偏导数组成的向量，指向函数值增长最快的方向
- 链式法则：复合函数求导的方法，是反向传播算法的数学基础

🧠 核心认知：梯度是损失函数变化最快的方向；梯度下降是沿着梯度反方向微调权重，是深度学习模型主体训练的核心方式。

#### 1.1.3 概率统计

核心原理：用概率分布描述数据的不确定性，通过最大似然估计等方法让模型拟合数据分布。

关键概念：

- 概率分布：描述随机变量取值的概率规律（如正态分布、伯努利分布）
- 最大似然估计：找到使观测数据出现概率最大的模型参数
- 贝叶斯定理：描述条件概率之间的关系，是贝叶斯机器学习的基础

#### 1.1.4 信息论

核心原理：用熵量化信息的不确定性，通过交叉熵衡量模型预测与真实标签之间的差异。

关键概念：

- 熵：描述随机变量的不确定性程度，熵越大，不确定性越高
- 交叉熵：衡量两个概率分布之间的差异，是分类任务最常用的损失函数

🧠 核心认知：交叉熵损失函数是深度学习分类任务的标准损失函数。

## 二、机器学习基础

### 2.1 机器学习三大范式

#### 2.1.1 监督学习

核心原理：使用带标签的训练数据，让模型学习输入到输出的映射关系。

核心任务：

- 分类：预测离散标签（如图片分类、垃圾邮件识别）
- 回归：预测连续值（如房价预测、销量预测）

代表算法：线性回归、逻辑回归、决策树、随机森林、SVM

深度学习的介入方式：图像分类、语音识别（端到端，无需人工提取特征）

#### 2.1.2 无监督学习

核心原理：使用无标签的训练数据，让模型自动发现数据中的模式和结构。

核心任务：

- 聚类：将相似的数据分组（如用户分群、异常检测）
- 降维：将高维数据映射到低维空间（如 PCA、t-SNE）

代表算法：K-means、DBSCAN、PCA

深度学习的介入方式：生成式模型（GAN 生成图片）、自监督预训练（BERT 通过掩码预测自造标签）

#### 2.1.3 强化学习

核心原理：智能体通过与环境交互，根据获得的奖励信号不断优化行为策略，以最大化长期累积奖励。

核心概念：

- 马尔可夫决策过程（MDP）：描述强化学习问题的数学框架
- 策略：智能体的行为函数，决定在给定状态下采取什么动作
- 奖励：环境对智能体动作的反馈信号

代表算法：Q-learning（值函数方法）、DQN（值函数 + 深度学习）、PPO（策略梯度方法）。三者分属强化学习三大主流路线——Q-learning（值函数）、DQN（值函数+深度学习）、PPO（策略梯度+信任域），各自适用于不同场景。

深度学习的介入方式：游戏博弈（AlphaGo 含监督学习 + 强化学习）、机器人运动规划、RLHF（大模型对齐技术）

⚠️ 注意事项：强化学习与深度学习是正交关系——强化学习是独立于监督/无监督范式的机器学习分支，深度学习是实现强化学习中策略/值函数近似的工具。深度强化学习（DRL）才是二者的融合产物。

### 2.2 核心通用概念

| 概念            | 定义                                                         |
| :-------------- | :----------------------------------------------------------- |
| 过拟合 / 欠拟合 | 过拟合：训练数据表现好，测试数据表现差；欠拟合：训练和测试数据表现都差 |
| 泛化能力        | 模型对未见过的新数据的预测能力，是机器学习的核心目标         |
| 偏差-方差权衡   | 偏差是模型预测的平均误差，方差是模型预测的波动程度；降低偏差通常增加方差，需找到平衡点 |
| 损失函数        | 衡量模型预测与真实标签之间差异的函数，是模型训练的优化目标   |
| 优化器          | 根据损失函数的梯度更新模型权重的算法（如 SGD、Adam）         |
| 评估指标        | 衡量模型性能的指标（如准确率、精确率、召回率、F1值）         |

⚠️ 注意事项：传统机器学习不会被深度学习完全取代，二者是互补关系。传统机器学习适合小数据、结构化数据任务，可作为 Agent 的辅助工具。

🔑 关键区分：三大范式是"问题维度"，深度学习是"解法维度"。深度学习不是第四大范式，而是实现三大范式的一种高级手段。传统机器学习也能实现三大范式，但深度学习的优势在于"端到端"——输入原始像素/波形，直接输出动作或标签，无需人工提取特征。

## 三、深度学习核心

### 3.0 总结概括

深度学习体系分为四个层级：

| 层级 | 名称                | 实质内容                                                     | 核心职责                                                     |
| :--- | :------------------ | :----------------------------------------------------------- | :----------------------------------------------------------- |
| 1    | 底层数学与优化理论  | 神经元模型（线性+激活）、前向传播、反向传播（链式法则）、损失函数（CrossEntropy/MSE）、优化器（SGD/Adam/AdamW）、正则化（Dropout/Weight Decay）、学习率调度 | 定义"模型如何从数据中学习"的完整数学规则与参数更新闭环逻辑。是绝对地基，所有上层实现必须严格遵循，永不改变 |
| 2    | 计算框架与执行引擎  | 训练框架（PyTorch/TensorFlow/JAX/MXNet）含自动微分；推理引擎（ONNX Runtime/TensorRT/OpenVINO/RKNN Runtime）不含自动微分 | 训练框架提供张量运算、自动微分、GPU/NPU硬件加速；推理引擎执行算子融合、量化压缩、硬件指令映射，完成单向前向推理 |
| 3    | 模型架构设计        | CNN（ResNet/EfficientNet）、RNN/LSTM/GRU、Transformer（GPT/BERT/ViT）、Mamba（SSM）、RWKV（线性注意力）、Hybrid（CLIP）、MoE（Qwen-Max） | 定义数据在模型中的前向传播路径、特征提取交互机制、参数组织方式，决定感受野、序列建模能力与计算复杂度 |
| 4    | Hugging Face 生态层 | transformers（AutoModel统一加载）、tokenizers/sentencepiece、safetensors、peft（LoRA）、trl（RLHF）、datasets/evaluate、HF Hub | 提供跨架构、跨框架的统一模型接口与模型仓库规范，内置对话模板与多模态Processor，编排微调/评估/部署工具链。本身不执行数值计算 |

依赖链路：底层数学原理约束规则 → 架构设计数据流向 → 框架执行数值计算 → HF 生态调度编排

### 3.1 通用底层原理

核心原理：通过堆叠多层非线性变换的神经网络，自动从数据中学习层次化的特征表示。

神经网络基本单元：

- 神经元：接收输入，进行线性变换（y = wx + b），然后通过激活函数引入非线性
- 全连接层：每个神经元与上一层所有神经元相连，实现特征的全局线性组合
- 激活函数：引入非线性，让神经网络能够拟合复杂的非线性函数（如 ReLU、SiLU、GELU）
- 归一化层：加速训练、稳定梯度（如 Batch Normalization、Layer Normalization）

训练核心流程：

1. 前向传播：输入数据通过网络层层计算，得到预测结果
2. 损失计算：用损失函数计算预测结果与真实标签之间的差异
3. 反向传播：根据链式法则，从输出层到输入层逐层计算损失对每个权重的梯度
4. 梯度下降：优化器根据梯度更新模型权重，减小损失

🔑 关键区分：判别式模型（分类/回归）学的是"边界"（这张图是猫还是狗），训练流程统一为前向→损失→反向→梯度下降，区别仅在特征提取模块。生成式模型（GAN、扩散模型）学的是"分布"（猫长什么样，然后画一只），训练流程各有不同。

### 3.2 训练推理框架

核心定位：将底层数学理论落地执行的代码运行基座，为全部网络架构提供张量运算、自动求导、GPU/NPU 硬件加速等底层执行能力。

⚠️ 注意事项：任意一种网络架构，自身只定义数据流转拓扑逻辑，无法独立完成数值计算；必须调用框架内置算子，才能执行前向传播与反向梯度更新。

四大主流框架：

- PyTorch：动态图执行，LLM/VLM/Mamba/RWKV 绝大多数开源模型基于 PyTorch 训练，Hugging Face 生态默认后端
- TensorFlow：静态图 + Eager 模式，传统 CV 工业项目与移动端部署（TFLite）仍有存量
- JAX：函数式 + XLA 编译，Google DeepMind（Gemini）、Mamba 实验性实现使用
- MXNet：Apache 归档，已退出主流生态

#### 3.2.1 自动微分

什么是自动微分？

自动微分（Autograd）是深度学习框架内置的"求导计算器"。它能自动追踪模型里的每一个数学操作（加减乘除、矩阵乘法、激活函数），并精确算出损失函数对每一个权重参数的偏导数（梯度）。

它在训练中具体干什么？

它是反向传播的代码实现：

1. 前向跑一遍：输入数据算出预测结果，并算出总损失 Loss
2. 自动反向追踪：框架根据 Loss，沿计算路径自动倒推，用链式法则算出每一层参数的梯度
3. 交给优化器：梯度传给优化器（如 Adam），优化器更新权重

训练框架 vs 推理引擎的核心区隔：

| 对比维度       | 全功能训练框架（PyTorch/TF/JAX）                         | 纯推理引擎（ONNX Runtime/TensorRT）                   |
| :------------- | :------------------------------------------------------- | :---------------------------------------------------- |
| 是否含自动微分 | 包含                                                     | 不包含                                                |
| 内部实情       | 内置完整的 autograd 引擎，运行时动态构建计算图并实时求导 | 只有前向计算算子（Conv、MatMul、Add），无反向求导逻辑 |
| 能做什么       | 既能前向（推理），也能反向（训练）                       | 只能前向计算。输入权重→输出结果，结束                 |
| 能不能训练     | 能。能算梯度，可调用优化器更新权重                       | 绝对不能。无"求导"功能模块                            |

结论：推理引擎不支持训练，本质是因为其代码库中完全移除了自动微分模块，只保留轻量级前向计算算子，以换取更小的体积和更极致的推理速度。

### 3.3 四大主流神经网络架构

#### 3.3.1 CNN 卷积神经网络

核心原理：通过卷积核在输入数据上滑动，提取局部特征；利用权值共享减少参数数量；通过池化层降维，扩大感受野。

核心模块：

- 卷积层：提取局部特征（边缘、纹理、形状）
- 池化层：降低特征图尺寸，减少计算量，增强特征鲁棒性
- 全连接层：将卷积提取的特征映射到输出空间

适用场景：视觉感知任务（Agent 的"眼睛"），如图像分类、目标检测、图像分割

代表模型：ResNet、YOLO、VGG、MobileNet

#### 3.3.2 RNN/LSTM 循环神经网络

核心原理：通过循环隐状态传递历史信息，处理序列数据。LSTM 通过门控机制（输入门、遗忘门、输出门）解决了传统 RNN 的梯度消失问题。

适用场景：在大语言模型（LLM）领域 Transformer 是主流基座，RNN/LSTM 退居二线。但在以下场景中，RNN/LSTM 仍是主力：

- 时序预测/异常检测：多元时间序列建模，LSTM/GRU 与 Transformer 各有胜负
- 传感器信号处理：实时性要求高、序列极长的工业信号
- 低算力端侧设备：STM32/低端 MCU 上，LSTM 推理算力开销远低于 Transformer

代表模型：LSTM、GRU

🔑 关键区分：RNN/LSTM 与 Transformer 是互补关系，而非取代关系。不能一棍子打死说 RNN/LSTM"被取代"。

#### 3.3.3 Transformer

核心原理：通过多头自注意力机制，直接计算序列中每个位置与所有位置的关联，实现全局上下文建模；通过位置编码引入序列的位置信息。

核心模块：

- 多头自注意力：将输入特征映射为多个头，分别计算注意力，然后拼接结果，捕捉不同维度的语义关联
- 前馈网络（FFN）：对每个位置的特征进行非线性变换
- 残差连接与 LayerNorm：加速训练，防止梯度消失

适用场景：语言、逻辑、多模态任务（Agent 大脑的核心）

代表模型：GPT、LLaMA、BERT、ViT

🧠 核心认知：纯 Transformer 大模型不含卷积。卷积不是所有模型必备，纯大语言模型可以完全不用卷积。

#### 3.3.4 Mamba 与 RWKV

**Mamba**

核心原理：通过选择性状态空间模型（Selective SSM，S6）的线性递推机制实现长序列建模。Mamba 建立在连续时间控制系统的状态空间模型基础上，其离散形式为 xt+1=Axt+But，yt=Cxt+Dut，是控制论导出的状态递推框架。时间复杂度 O(n)，远低于 Transformer 的 O(n²)。

适用场景：超长上下文 Agent、大模型推理加速

代表模型：Mamba（通用状态空间块，可搭 LLM/VLM/语音全模态）

**RWKV**

核心原理：RWKV（Receptance Weighted Key Value）是一种结合了 Transformer 高效并行训练与 RNN 高效推理的新型架构。其核心是线性注意力机制（Linear Attention）+ Token Shift，官方定位为 RNN 的变体。RWKV 在数学上可以等价表达为状态空间模型的形式，但其设计源头是线性注意力近似，而非控制论状态空间模型。

适用场景：超长上下文 Agent、大模型推理加速

代表模型：RWKV（纯文本大模型架构，兼容 Hugging Face 格式）

- Mamba = 原生 Selective‑SSM（控制论状态空间模型）
- RWKV = RNN 变体、线性注意力，数学上可等价表达为 SSM 形式，但设计源头不是控制论 SSM

🔑 关键区分：两者虽然都致力于用线性复杂度替代 Transformer 的 O(n²)，但实现原理与设计源头存在本质差异。

### 3.4 Hugging Face 生态层

核心定位：独立于引擎、架构的标准化工具链与模型仓库，无底层计算能力。

核心组件：

- transformers：统一加载接口（AutoModel），支持全架构自动路由
- tokenizers / sentencepiece：分词与编码
- safetensors：安全权重序列化格式（已全面取代 .ckpt 和 .bin）
- peft：LoRA、QA-LoRA 等参数高效微调
- trl：基于强化学习的 RLHF 训练（PPO、DPO）
- datasets / evaluate：数据集加载与标准评估指标
- HF Hub：模型仓库与数据集托管平台

核心作用：

- 一套加载接口兼容 CNN/RNN/Transformer/Mamba 全部架构
- 自动适配 PyTorch/TensorFlow/JAX 三大计算引擎
- 统一 HF 模型文件夹规范（config.json、分词器、分片权重）
- 内置对话模板、图像预处理、批量推理逻辑
- 编排微调、评估、部署的完整工具链

依赖链路：HF 工具 → 实例化对应架构网络 → 调用计算引擎完成前向传播推理/训练

### 3.5 深度学习优化技术

#### 3.5.1 梯度类优化

核心原理：根据损失函数的梯度，沿着梯度反方向微调模型权重，逐步减小损失。

代表算法：

- SGD（随机梯度下降）：每次使用一个样本更新权重，速度快，波动大
- Adam：结合动量和自适应学习率，收敛快，稳定性好，是目前最常用的优化器
- 学习率调度：训练过程中动态调整学习率，前期用大学习率快速收敛，后期用小学习率精细调整（Step、Cosine、Warmup 等策略）

⚠️ 注意事项：在深度神经网络的主体训练中，基于梯度的优化（如 SGD、Adam）是绝对主流范式，在工业界占据主导地位。但需要注意：

1. 决策树和随机森林的训练不依赖梯度下降；而 XGBoost 等梯度提升树（GBDT）本质上使用梯度下降来优化。
2. 进化策略（ES）可作为强化学习中策略网络的替代训练方法，直接优化参数，属于策略网络的主体训练范畴。

#### 3.5.2 非梯度类优化

核心原理：不依赖梯度，通过群体随机搜索和优胜劣汰迭代寻优，适合离散组合优化问题。

代表算法：

- GA 遗传算法：模仿生物进化，通过选择、交叉、变异迭代筛选最优解
- PSO 粒子群算法：模仿鸟群觅食，通过粒子向自身最优和全局最优位置靠拢寻优
- ACO 蚁群算法：模仿蚂蚁觅食路径信息素更新机制

适用场景：网络结构搜索（NAS）、超参寻优、初始权重优化

⚠️ 注意事项：仿生算法在绝大多数深度学习场景中仅用于前置结构/超参/初始权重寻优。但进化策略（ES）可作为强化学习中策略网络的替代训练方法，属于"主体训练"范畴。

#### 3.5.3 正则化

核心原理：通过限制模型的复杂度，防止过拟合，提升泛化能力。

代表技术：

- Dropout：训练时随机丢弃部分神经元
- L1/L2 正则：在损失函数中加入权重的惩罚项
- 早停（Early Stopping）：当验证集损失不再下降时停止训练

## 四、大模型基础

### 4.1 大模型核心技术栈

#### 4.1.1 预训练

核心原理：使用海量无标注文本数据，通过自监督学习任务（如预测下一个 Token），让模型学习通用的语言规律和常识知识，并将这些知识压缩进权重参数中。

核心特点：预训练后的大模型具备通用的语言理解和生成能力，可通过微调适配各种下游任务。

#### 4.1.2 微调

核心原理：在预训练模型的基础上，使用少量标注数据继续训练，让模型学会遵循指令、完成特定任务。

主流技术：

- 全量微调：更新模型的所有权重，效果好，计算成本高
- SFT（监督微调）：使用人类标注的指令数据微调，让模型学会遵循指令
- LoRA/QLoRA：低秩适配技术，只更新模型少量参数，计算成本低，效果接近全量微调

🔑 关键区分：微调可以注入新知识（垂直领域医学/法律模型正是靠微调吸收专业知识），但效率低、有灾难性遗忘风险、难以验证注入的具体内容。对于高精度、实时性强、频繁变动的事实知识，RAG 更优；对于需要固化到模型行为中的专业语感，微调更合适。

#### 4.1.3 对齐

核心原理：让大模型的输出符合人类的价值观和偏好，避免生成有害、虚假、偏见的内容。

主流技术：

- RLHF（基于人类反馈的强化学习）：先由人类标注员对模型输出进行排序，然后训练奖励模型，最后用强化学习算法（如 PPO）优化大模型
- DPO（直接偏好优化）：直接使用人类偏好数据优化模型，不需要显式奖励模型，但稳定性与 RLHF 各有优劣，学术界仍在讨论

### 4.2 大模型推理与增强技术

#### 4.2.1 原生推理

核心原理：自回归逐 Token 生成——每次生成一个 Token，将生成的 Token 加入上下文，再生成下一个 Token，直到生成结束符。

核心特点：

- 仅使用权重内压缩的参数化知识
- 不触发联网、不触发外部工具调用（指纯参数化推理模式）
- 推理成本与输入输出 Token 数量成正比

🧠 核心认知：原生大模型在纯参数化推理模式下不联网、不查库，仅使用权重内压缩的知识。

#### 4.2.2 工业级增强推理：RAG 检索增强

核心原理：将外部知识库中的知识检索出来，与用户问题一起拼接成 Prompt，让大模型基于检索到的真实知识生成答案。

标准三步模式：

1. Retrieval（检索）：将用户问题向量化，在外部知识库中检索相关文档片段
2. Augmentation（增强）：将检索到的支持数据拼接到提示词中
3. Generation（生成）：LLM 基于增强后的提示词生成回答

完整流程细化：

1. 用户提问
2. 问题解析与改写（可选）
3. 检索本地知识库 / 全网搜索引擎
4. 检索结果相关性排序与去重
5. 提取高可信度参考文本
6. 构建 Prompt：系统指令 + 用户问题 + 检索参考资料
7. 送入大模型生成答案

🧠 核心认知：RAG 负责提供事实，大模型负责生成和推理，二者边界清晰。

⚠️ 注意事项：大模型在纯参数化推理模式下不会自己主动联网搜索，所有检索动作由外部 RAG 模块完成。

## 五、Agent 智能体

### 5.1 Agent 核心定义与五大组件

🧠 核心认知：Agent = 大脑（大模型）+ 记忆 + 规划 + 工具 + Skills

大模型只是 Agent 的大脑，不是完整的 Agent。五大组件分工清晰，缺一不可。

#### 5.1.1 大脑（大模型）

核心职责：决策、语言生成、逻辑推理

原理详解：作为 Agent 的核心，接收规划模块处理后的上下文，生成决策、推理过程和自然语言回答。

工程映射：RKLLM（本地 NPU 推理）、llama.cpp（CPU 推理）、云端 API（DeepSeek/GPT/Claude）

#### 5.1.2 记忆模块

核心职责：管理短期上下文、长期向量记忆、技能使用记录、动态加载与卸载

四层记忆架构：

1. 短期上下文记忆：当前对话窗口内的内容，直接送入大模型
2. 工作记忆：当前任务的中间执行状态
3. 长期向量记忆：历史对话和知识库内容，存储在向量数据库中
4. 技能记忆：已安装的 Skills 清单和使用记录

动态加载与卸载：根据当前任务需要，只将相关的记忆内容加载到上下文，无关内容卸载，避免上下文爆炸。

工程映射：LlamaIndex（记忆构建）+ Chromadb（向量存储）

⚠️ 注意事项：记忆不是存得越多越好。关键是"该记的记住，该忘的忘掉"——上下文窗口有限，把无关历史塞进去只会让大模型分心。

#### 5.1.3 规划模块

核心职责：任务拆解、步骤编排、执行状态管理、失败回滚、反思修正、多 Skill 组合编排

原理详解：将用户的复杂任务拆解为可执行的子任务，编排执行步骤，管理每个步骤的执行状态，当步骤失败时进行回滚和重试，任务完成后进行反思总结。

多 Skill 组合编排：根据任务需要，将多个 Skills 按照串行、并行或条件分支的方式组合起来，完成复杂的专业任务。

工程映射：LangGraph（精确状态机控制，推荐）、CrewAI（角色扮演式编排）、自写 while 循环（最轻量）

#### 5.1.4 工具调用

核心职责：执行单一外部动作（API/CLI/数据库/GPIO）

原理详解：作为 Agent 与外部世界交互的接口，接收规划模块的指令，执行单一的外部动作，并将结果返回给规划模块。一个工具只做一件事。

⚠️ 注意事项：工具不做高层任务决策（如"下一步该调用什么"），但允许执行层局部决策（如超时重试、错误码映射、返回结果集筛选）。

工程映射：MCP 协议（标准工具集成方式）、自写硬件驱动函数（GPIO/摄像头/PWM 封装）

🔑 关键区分：工具 = 单一 API 调用；Skill = 完整工作流程 + 最佳实践 + 错误处理。

#### 5.1.5 Skills

核心职责：提供专业工作流程、最佳实践、错误处理模板

原理详解：将特定领域的专业知识和工作流程封装成标准化的 Skill 包，让 Agent 无需重新学习即可胜任专业任务。

工程映射：SKILL.md 文件

⚠️ 注意事项：Skill 不跨任务调度，不越权做全局决策。

五大组件协作示例：用户说"帮我检查这个传感器是否正常"。大脑判断意图 → 规划拆解步骤（初始化 → 读数 → 校验 → 报告）→ 调用工具执行 GPIO 读取 → 如失败则回滚重试 → 记忆存储结果 → 大脑生成最终报告。

### 5.2 单 Agent 主流架构模式

| 模式                 | 核心思想             | 关键特征                                                     |
| :------------------- | :------------------- | :----------------------------------------------------------- |
| ReAct                | 推理与行动交织       | Thought-Action-Observation（TAO）闭环：每一步先显式输出"思考内容（Thought）"和"行动指令（Action）"，再利用环境反馈（Observation）更新后续推理，循环直到任务完成。最基础、最常用的 Agent 循环。 |
| Reflexion            | ReAct + 语言反馈反思 | 核心创新：不更新模型权重，而是通过语言反馈强化智能体。任务失败时，智能体将失败经验以自然语言形式写入情景记忆缓冲区（Episodic Memory Buffer），在下一轮尝试中作为上下文信号注入提示词，引导模型绕开错误。无需任何基于梯度的权重更新。 |
| Plan-Execute-Reflect | 规划→执行→反思三阶段 | 标准范式为三阶段：① Planning（规划）：规划器 LLM 使用可用工具生成初始分步计划；② Execution（执行）：按步骤顺序执行；③ Re-evaluation/Reflect（反思/重规划）：每一步执行后，重规划器（Replanner）根据中间执行结果动态重新评估计划，跳过、添加或更改后续步骤。缺失反思环节的系统不具备容错能力。 |
| 工业级混合           | 上述模式融合         | Claude Code 等产品内部用 ReAct 类循环进行代码探索与修改，原生集成 Skills 标准 |

### 5.3 Agent 能力扩展：Skills 开放标准

起源：Anthropic 于 2025 年 10 月在 Claude Code 中首次推出 Skills 功能，同年 12 月联合生态伙伴正式升级为 Agent Skills 开放标准（Open Standard），上线 [agentskills.io](https://agentskills.io/) 官网。

核心原理：渐进式披露——Agent 启动时只加载 SKILL.md 清单（包含 Skill 的名称、描述、输入输出），当需要调用某个 Skill 时再加载完整的指令和代码。这解决了传统 Agent 一次性加载所有指令导致的上下文爆炸问题。

Skill 文件标准结构：

- 文件夹：每个 Skill 一个独立的文件夹
- SKILL.md：包含 YAML 头（元数据：name、description）和 Markdown 指令（工作流程、最佳实践、错误处理）
- scripts/：可选，包含 Skill 执行所需的脚本文件

与工具调用的本质区别：工具 = 单一 API，Skill = 完整工作流程 + 最佳实践 + 错误处理。

Skill 开发流程：编写 SKILL.md → 本地安装测试 → 发布到社区分享

### 5.4 多 Agent 系统

主流架构：

- 主从式：一个主控 Agent 负责任务分配和协调，多个专业 Agent 负责执行具体任务
- 联邦式：多个平等的 Agent 协同工作，共同完成任务
- 层级式：多层 Agent 分工，高层负责战略规划，低层负责战术执行

核心技术：角色分工、通信协议、任务分配、冲突解决

工程映射：AutoGen（多 Agent 协作框架）、CrewAI（角色驱动编排）、LangGraph（子图/层级图拓扑）

| 5. 上下文工程                    | 管理和优化传递给模型的上下文内容，确保其高效、相关且不超限   |
| 6. 编排 + Hooks                  | 提供任务编排、生命周期钩子，管理执行流程并支持状态持久化与恢复 |

## 六、工程化落地

### 6.1 模型工程化（优化计算量）

核心目标：让模型跑得更快、更省算力，降低推理延迟和硬件成本。

核心技术：

- 量化：将模型的权重和激活从 32 位浮点数转换为 16 位、8 位甚至 4 位整数，减少计算量和内存占用，精度损失很小
- 剪枝：移除模型中不重要的权重和神经元，减少模型参数数量
- 知识蒸馏：用大模型（教师模型）训练小模型（学生模型），让小模型具备接近大模型的能力

标准部署链路：PyTorch 模型 → ONNX 转换 → RKNN 量化 → 边缘设备 NPU 推理

⚠️ 注意事项：模型工程化的操作（量化、剪枝）会改变模型权重精度与分布，从而影响输出数值分布。

### 6.2 Agent 工程化（优化数据量/Token 成本及任务流可靠性）

核心目标：降低输入输出 Token 消耗，提升 Agent 运行效率和任务执行可靠性，降低推理成本。

与模型工程化的本质区别：

- 模型工程化：优化计算量（改模型本身）
- Agent 工程化：优化数据流与任务可靠性（不改模型，改输入输出组织方式）

优化方向（社区有探索性工具，尚未形成统一行业标准）：

- 上下文裁剪：自动裁剪长对话历史，只保留与当前任务相关的内容
- 记忆按需加载：将长期记忆存储在向量数据库中，按需检索加载
- CLI 输出过滤：压缩命令行命令的输出，去除无关的格式和冗余信息
- 跨会话记忆系统：高效管理跨会话的长期记忆

### 6.3 MLOps 与 AIOps

核心目标：实现 AI 模型和 Agent 的全生命周期自动化管理，提升开发效率和系统稳定性。

核心内容：

- 数据管理：数据采集、清洗、标注、版本管理
- 模型版本管理：模型训练、版本控制、模型仓库
- 监控与运维：模型性能监控、错误监控、资源监控
- A/B 测试：不同模型和 Agent 版本的对比测试
- Agent 全生命周期管理：Agent 开发、测试、部署、升级、下线
- 可观测性：Agent 执行轨迹追踪、Token 消耗监控、任务完成率统计（工具：LangSmith、LangFuse、AgentOps）

### 6.4 模型评测

| 评测类型      | 指标                                   |
| :------------ | :------------------------------------- |
| 传统 NLP 评测 | GLUE、BLEU、ROUGE                      |
| Agent 评测    | 任务完成率、轨迹相似度、人评协议       |
| RAG 评测      | 检索准确率、答案忠实度（Faithfulness） |

## 七、安全伦理与法规

### 7.1 技术安全

#### 7.1.1 模型安全

- 反蒸馏：防止攻击者通过查询模型输出，蒸馏出模型的权重和知识，保护模型知识产权
- 对抗攻击防御：防止攻击者通过构造恶意输入，让模型产生错误的输出
- 模型窃取防护：防止攻击者直接窃取部署的模型文件

#### 7.1.2 Skill 安全

- Skill 安全沙箱：隔离运行 Skill 代码，防止恶意 Skill 访问系统资源、窃取数据或破坏系统
- 权限控制：为每个 Skill 分配最小必要权限
- 输入输出过滤：过滤 Skill 的输入和输出，防止注入攻击和敏感信息泄露
- 恶意代码检测：扫描公共 Skill 库中的 Skill，检测恶意代码

#### 7.1.3 数据安全

- 数据隐私保护：对训练数据和用户数据进行脱敏处理，防止隐私泄露
- 数据加密：对存储和传输中的数据进行加密
- 访问控制：严格控制数据的访问权限

#### 7.1.4 越狱防御

- Agent 时代更常见的提示注入与越狱攻击（Prompt Injection / Jailbreak）
- 针对 Agent 的提示注入防御、系统指令保护、输入输出内容安全护栏

### 7.2 热点伦理问题

- 同事.skill：员工将自己的专业技能和工作经验封装成 Skill，引发职场隐私、知识产权归属和员工替代的争议
- 知识价值归属：RAG 检索生成内容的版权归属问题——是原作者、知识库提供者还是大模型厂商，目前全球没有明确的法律定论
- 数字分身被遗忘权：欧盟 AI 法案明确要求，用户有权要求删除自己的数字分身和相关数据
- 算法偏见与公平性：Agent 在决策过程中可能会继承训练数据中的偏见，导致歧视性结果

### 7.3 全球 AI 法规

| 法规                           | 核心内容                                                     |
| :----------------------------- | :----------------------------------------------------------- |
| 欧盟 AI 法案                   | 全球第一部综合性 AI 法规，将 AI 系统分为四个风险等级，对高风险 AI 系统实施严格监管 |
| 中国生成式 AI 服务管理暂行办法 | 对生成式 AI 服务的备案、数据安全、内容合规等方面做出明确规定 |
| 美国 AI 行政令                 | 要求联邦政府机构在使用 AI 时确保安全、可信和负责任           |

## 常见误解速查

| ❌ 常见误解               | ✅ 精准表述                                                   |
| :----------------------- | :----------------------------------------------------------- |
| PyTorch 是模型           | PyTorch 是深度学习计算框架，用于定义、训练和运行模型（如 Transformer、CNN），本身不包含任何模型参数或知识。 |
| 大模型存了所有知识       | 大模型将训练数据压缩为参数化的常识与模式，知识是模糊的、非精确的，有截止日期。高精度、时效性知识需通过 RAG 从外部权威源动态检索注入。 |
| 训练模型用了遗传算法     | 遗传算法等进化策略通常用于超参数搜索或神经架构搜索（NAS）等前置阶段；模型主体训练完全依赖基于梯度的优化（如 AdamW + 反向传播）。进化策略可作为强化学习中策略网络的替代训练方法，属于例外。 |
| Skill 就是工具调用       | Skill 是封装了工具调用、输入校验、错误重试、结果解析与业务逻辑的完整能力单元，而非裸 API 调用。 |
| Agent 工程化就是模型量化 | 模型工程化聚焦计算效率（量化/编译/部署），Agent 工程化聚焦任务流可靠性（记忆管理、规划回退、工具协同、状态持久化）。二者目标不同，常需协同。 |
| 大模型的上下文就是记忆   | 大模型上下文是临时、易失、长度受限的输入缓冲区；长期、结构化、可更新的记忆必须由外部向量库或数据库实现。 |
| 大模型天生会规划         | 大模型可生成看似合理的计划，但缺乏目标一致性、状态感知与回退机制；工业级 Agent 必须引入独立规划逻辑（如状态机、树搜索）保障可靠性。 |
| 微调能让模型记住新知识   | 微调可以注入知识，但效率低、有灾难性遗忘风险、难以验证；对于高精度、实时性强、频繁变动的事实知识，RAG 更优；对于需要固化到模型行为中的专业语感，微调更合适。 |

## 结尾总结

整个 AI 领域的发展，就是一个不断把"通用大模型"变成"能可靠解决实际问题的工业级 Agent"的过程。

- 大脑负责思考，记忆负责不忘，规划负责步步为营（含反思修正），工具负责动手，Skills 负责专业技能
- RAG 提供实时事实，模型工程化让它跑得快，Agent 工程化让它跑得聪明
- 安全伦理是它大规模服务社会的保险丝
